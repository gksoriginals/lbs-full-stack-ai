A prompt is the request-time context that specifies a task for an LLM.

It does not give the model new parameters. It determines what the model can condition on for this response.

The prompt as an interface

Make the task contract
inspectable.

A real application prompt is assembled from distinct components. Separating them makes ambiguity, evidence boundaries, and failure behaviour reviewable.

TaskExtract assessable course outcomes from the supplied syllabus.
Evidence boundaryUse only the syllabus. Do not infer an outcome that is not stated.
ConstraintsPreserve source wording. Flag ambiguity instead of forcing a label.
Output contractReturn JSON with an evidence span and needs_review.
ExamplesShow difficult boundaries only when the specification is not enough.
The model sees tokens, not your unstated intention.
Long context is position-sensitive

Inside the window
does not mean equally used.

Critical evidence can be present but hard for a model to use when it is buried in a long prompt.

Place stable rules clearly; keep evidence close to the task that needs it; test equivalent prompts with the evidence moved.

Prompt consolidation

Preserve the signal.
Remove the scatter.

As a task grows, consolidate repeated instructions, selected evidence, and decisions into one canonical context record.

Scattered context

“Use a rubric.”
old chat: “Output JSON.”
retrieved policy: 14 pages
“Don’t infer missing outcomes.”
repeated style instructions
→

Canonical context record

RequirementsExtract only stated outcomes; JSON schema.
Selected evidenceClauses 2.1, 2.4, 5.3 with source IDs.
DecisionsUse Bloom level only when explicit.
Open issueOutcome 4 remains ambiguous → review.

Consolidation reduces token cost and distraction. It can also lose exceptions—keep original sources available and never promote instructions inside untrusted documents.

Low-resource language prompting

Use the target language
as a testable choice.

Target-language prompts and examples can preserve terminology, grammar, and local meaning. They are not automatically better than English for every model.

Reasoning scaffolds and actions

Choose a technique to resolve
a known failure.

For a multi-step transformation, intermediate artefacts can make work checkable. When facts are missing, a tool observation can ground the next step.

Chain of thought

Useful for hard multi-step tasks when intermediate work can be verified.
