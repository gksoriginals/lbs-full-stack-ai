Not a fixed threshold

No universal parameter count defines “large.” The term describes the engineering regime in which a broadly trained language model can be prompted or adapted across many tasks.

Foundation model ≠ only language

An LLM is language-centred. A foundation model may span text, images, audio, and other modalities.

Request-time task specification

A prompt is not just a question.

It is the request-time package of instructions, examples, user input, and selected evidence that the model receives.

Goal — what response or transformation is required.
Constraints — scope, format, exclusions, and policy boundaries.
Evidence — source passages or tool results permitted to influence the answer.

Important boundary

Prompting changes the current request. It does not update the model’s learned parameters or create permanent memory.

Prompt = runtime context
Training = parameter update

Why text must be transformed

Text is open-ended.
Neural networks need numbers.

A tokenizer turns arbitrary text into a finite, reusable vocabulary of numeric units.

unpredictable→ IDs

Tokens can be words, subwords, punctuation, whitespace patterns, or byte sequences—not necessarily whole words.

Tokenizer

Text → token IDs → model input. Generated IDs → decoded text.

Why subwords?

They avoid requiring a separate vocabulary entry for every rare word, identifier, spelling variant, or code fragment.

From identifiers to representations

An ID is a label.
An embedding is a vector.

The embedding matrix turns a token ID into a learnable continuous representation that the network can transform.

Position is required too

Attention needs positional information. “Dog bites man” and “man bites dog” contain the same tokens in a different order.

Context changes meaning

“Bank” receives different contextual representations in “river bank” and “bank loan.”

Working memory for one response

The context window is bounded.

It is the token budget a model can attend to while producing this response.

The window makes tokens available; it does not decide which available token matters for the current prediction.

Why a limit exists

Attention has memory and compute costs as sequences grow. The model cannot treat unlimited history as input.

Capacity is not accuracy

Long context can contain more material; it does not guarantee that the model selects, interprets, or verifies it correctly.

The problem attention solves

Availability is not relevance.

The context window exposes many tokens. Attention decides which of those available tokens should influence this token now.

To interpret it, the model should prioritise animal rather than treat all earlier tokens equally.

Example

“The animal did not cross the street because it was too tired.”

Question: Which earlier token should shape the representation of it?

animal → highly relevant
street → not the antecedent

The concrete objective

Make it carry the meaning of animal—not street.

The model must first identify the right antecedent among many available tokens, then use only that selected token’s information to update it.

1. The request: Query (Q)it produces a learned request: “Which earlier token should inform me?”
2. The comparison: Key (K)Each candidate—animal, street, …—gets a learned tag that can be compared with that request.
3. The transfer: Value (V)Once animal receives high relevance, its learned information is mixed into the representation of it.
Why more than one head?

One relevance pattern is not enough for all the relationships in language.

Different heads can learn different ways to relate tokens: antecedents, syntax, negation, nearby phrases, or long-range dependencies.

Head 1Does animal explain it?
Head 2How does tired modify the event?
Head hAnother learned relationship pattern.

Same Transformer ideas, different visibility

Encoder models, decoder models,
and encoder–decoder models.

BERT-style
encoder-only

Sees: left and right context.

Trains: reconstruct masked tokens.

Used for: classification, token labelling, embeddings, extractive QA, retrieval.

GPT-style
decoder-only

Sees: earlier tokens only.

Trains: predict next token.

Used for: chat, text generation, code completion, open-ended continuation.

T5 / BART
encoder–decoder

Sees: source in encoder; past target in decoder.

Trains: source-to-target reconstruction.

Used for: translation, summarisation, controlled transformation.

Learning and generation

Pre-training learns patterns.
Decoding chooses a response.

The model learns by comparing its prediction with a known training token. At runtime, it selects a token from a score distribution and repeats.

Decoding controls

Temperature changes how concentrated the next-token distribution is; it is not a factuality control.

Top-k / top-p restrict candidate tokens before sampling. Max output / stop sequences bound when generation ends.

An LLM is a probabilistic sequence model with learned representations—not a reasoning oracle, database, or autonomous authority.
