Generative and reasoning tiers

More reasoning is not
always a better choice.

All LLMs generate tokens. Reasoning-capable models usually spend more inference-time effort on difficult tasks—trading latency and cost for potential task improvement.

Efficiency

mini · nano · Haiku · Flash-Lite

High-volume routing, tagging, simple extraction, well-defined transforms.

→
Balanced

Flagship / reasoning

Model selection

Start with the least expensive model that passes the full threshold.

Use task evidence—not fluent demos or a generic leaderboard—to decide whether escalation is justified.

Efficiency tier
Does it meet source fidelity, schema, latency, and cost targets?
Balanced tier
Escalate if the smaller model fails a measurable task criterion.
Reasoning tier
Use when the additional inference effort improves hard cases.
High volume: begin with an efficiency tier and validate its accepted-result rate.

Claude

from anthropic import Anthropic
client = Anthropic()
r = client.messages.create(
  model="<MODEL_ID>",
  max_tokens=1024,
  messages=[{"role":"user",
    "content":"Extract outcomes as JSON."}]
)
print(r.content[0].text)

Request configuration

A prompt is only one part
of model behaviour.

The model, request parameters, tools, and output contract together determine what the system can do.

Illustrative configuration

config = {
  "max_output_tokens": 800,
  "temperature": 0.2,
  "seed": 42,
  "response_schema": OUTCOME_SCHEMA,
}

Two important limits

Low temperature ≠ factual.
A seed is useful for testing, but does not guarantee identical output after a model or platform change.
