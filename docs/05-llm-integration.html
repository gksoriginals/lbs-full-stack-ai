class PolicyAnswer(BaseModel):

        "eligible", "ineligible",
        "insufficient_evidence"
    ]
    rationale: str
    citations: list[str]
    requires_human_review: bool

Validate after generation

answer = PolicyAnswer.model_validate_json(text)
permitted = {excerpt.source_id for excerpt in excerpts}

if not set(answer.citations) <= permitted:
    raise ValueError("Unsupported citation")
Retrieval augmented generation

Current, scoped evidence
before generation.

RAG is retrieval + generation—not merely “use a vector database.”

flowchart LR
  D[Approved documents] --> I[Parse, chunk, attach metadata]
  I --> E[Embed and index]
  Q[User question] --> F[Authorise and filter]
  F --> R[Keyword, vector, or hybrid retrieval]
  E --> R
  R --> K[Top evidence + source IDs]
  K --> L[LLM: answer from evidence]
  L --> V[Validate citations / abstain]
Authorise before retrieval. A relevant document that the user may not access must never enter the prompt.
Tool calling

The model can request.
Only code can act.

Tool arguments are untrusted input. The application validates, authorises, executes, and returns a typed result.

sequenceDiagram
  participant L as LLM
  participant A as Application
  participant T as Approved tool
  L-->>A: tool_call(name, JSON arguments)
  A->>A: schema + permission + policy check
  alt allowed
    A->>T: Execute with server credentials
    T-->>A: trusted result
    A-->>L: tool_result
    L-->>A: user-facing response
  else denied or invalid
    A-->>L: structured error or no result
  end

A narrow tool contract

{
  "name": "lookup_attendance_rule",
  "parameters": {
    "type": "object",
    "properties": {
      "programme": {"type": "string"},
      "semester": {"type": "integer"}
    },
    "required": ["programme", "semester"],
    "additionalProperties": false
  }
}

Never hand over authority

Use narrow tools, server-side credentials, permission checks, timeouts, audit logs, and confirmation for consequential actions.

Observe, evaluate, improve

Logs explain a request.
Evaluation explains change.

flowchart LR
  P[Production traces] --> S[Protect sensitive data]
  S --> F[Sample failures and edge cases]
  F --> E[Versioned evaluation set]
  E --> C[Compare model, prompt, retrieval]
  C --> D[Deploy or reject]
  D --> P
Trace the configuration, not only the final answer. Capture model ID, prompt version, retrieval IDs, parameters, tools, schema result, latency, cost, retries, and user feedback.
